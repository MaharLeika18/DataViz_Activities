 ### 1. Discovery
 
- **Specific objectives:**
Identify why Finance and Operations are seeing a discrepancy in the revenue amount for the same sales data and the reason for what the CEO needs to do for next year's inventory.
- **Data requirements:** 
Customer Data (cust_name, region) from the Web Form, Sales Data (transaction_id, order_date, amount_paid, status) from the transactional Database. Data for shipping related to the third party text files are not included in the data set and will have to be added in the future.
- **Deployment goals:** 
Create a problem statement document that includes the sources of the data, likely causes of the discrepancy, (e.g., duplicated data, data inconsistent statuses, data inconsistent region names), and what should be investigated next.

### 2. Data Preparation 

- **Specific objectives:** 
Explore and profile raw sales data (juanmart_raw_sales.csv) to identify data quality issues, and clean the data with a script ready for loading into the warehouse.
- **Data requirements:** 
Data from the transaction_id, cust_name, region, order_date, amount_paid, and status field, all of which were checked for consistency, missing data, and for any duplications.
    - Duplicate transactions (1001, 1005), Missing cust_name (2 nulls), Missing amount_paid (2 nulls), Inconsistent region spelling ("NCR" vs "ncr"), and Inconsistent date format ("-" vs "/").
- **Deployment goals:**
Produce a Python script that can do the following: Remove all duplicate rows from the data set, Fill in missing amount_paid with the median value, Fill missing cust_name with "Unknown", Standardize region names, Standardize date format, Output a clean CSV.

### 3. Model Planning    

- **Specific objectives:** 
Create a consistent formula for revenue recognition (Completed transactions only) for future periods for Finance and Operations to use. Identify other metrics that support the inventory planning process like number of cancellations or returns by region or time period.
- **Data requirements:** 
The amount_paid and status (true revenue from Completed orders only); region and order_date (to analyze by region and by time).
- **Deployment goals:** 
A documented collection of metric definitions (e.g., "Revenue = sum of amount_paid where status = Completed") and anticipated queries and reports that Finance, Operations, and the CEO agree to ahead of the development of dashboards or models.

### 4. Model Building   

- **Specific objectives:** 
Create a correct database design for customer information, transaction data, and shipping data, then make them all interconnected, but not repeated or duplicated.
- **Data requirements:** 
Customers table (cust_name, region); Transactions table (transaction_id, order_date, amount_paid, status, linked to customer); Shipping table (to be added when logistics data is added up). The tables are connected by an ID (customer_id, transaction_id).
- **Deployment goals:**
A normalized database schema in which the Customers, Transactions, and Shipping tables are separate, and are ready to be populated and queried for reporting purposes.

### 5. Communicate Results    

- **Specific objectives:** 
Resolve discrepancy in previously communicated revenue amounts and metrics in front of Finance, Operations and the CEO as specific objectives.
- **Data requirements:** 
Cleaned and modeled data on revenue, region based sales and cancellation/return rates.
- **Deployment goals:** 
A dashboard that provides consistent revenue numbers and regional sales/return trends, approved and authorized by Finance, Operations and the CEO.

### 6. Operationalize    

- **Specific objectives:** 
Ensure data pipeline continues to run automatically when new customer, sales and shipping data arrives, and not just for one-time cleanup.
- **Data requirements:**
Continuous incoming data integration from Web form, transactional database and shipping files from third parties.
- **Deployment goals:**
A version of the cleansing script (and later the shipping data integration), automated and scheduled to allow for a continuous and reliable up-to-date data warehouse.
